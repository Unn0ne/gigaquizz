# Проверка двух веток — 10 сентября 2026

`simple-files` и `postgres-kafka` подключены к полному приложению: сайт, кабинет, создание, голосование, закрытие и окончательные результаты. Обе используют контракт `202 recorded` и точный пересчёт первого выбора полного ID после закрытия.

Проверки выполнены на одном Mac с Apple M1 Pro, 32 GiB RAM и Go 1.26.1. Kafka — три локальных брокера 4.3.1, PostgreSQL — 16.3. Для браузера используется установленный Chrome через Playwright 1.63.0. Это проверка поведения и восстановления, не измерение предельной пропускной способности.

| Проверка | simple-files | postgres-kafka |
|---|---|---|
| Go-тесты с race detector, vet | Пройдены | Пройдены |
| Сборка всех команд ветки | Пройдена | Пройдена |
| HTTP: 12 подтверждённых попыток, конфликтующие повторы | 3 уникальных голоса, `[2,1]` | 3 уникальных голоса, `[2,1]` |
| SIGKILL приложения и продолжение внутри исходной минуты | Пройдено | Пройдено |
| SIGKILL без штатного закрытия, восстановление после дедлайна | Точный окончательный итог | Точный окончательный итог |
| Новый и повторный POST после закрытия | `410` | `410` |
| Ещё один перезапуск после публикации результата | Итог не изменился | Итог не изменился |
| Chrome: полный набор, включая реальное голосование | 5/5, 103,65 с | 5/5, 101,94 с |

Каждый HTTP-тест создаёт своё хранилище или схему и управляет только своим дочерним приложением. После перезапуска административная сессия отзывается. Исходные интервалы не меняются. Подтверждённые попытки и уникальные участники считаются отдельно.

Первый браузерный прогон прошёл 4 из 5 тестов в каждой ветке и выявил ошибку ожидания в самом E2E: проверка поля могла опередить загрузку страницы и IndexedDB. После исправления обе ветки прошли 5/5 тестов без нестабильных результатов. Проверены 5 сохранённых попыток → 3 уникальных участника, две потери ответа уже после настоящего ACK, две вкладки с одним ID, отказ поздних запросов, ожидание и окончательные результаты, выход администратора. Агрегаты первого неудачного прогона сохранены вместе с окончательными отчётами.

Файловые проверки дополнительно покрывают оборванный последний frame, отказ при CRC повреждении, конкурирующего владельца, незавершённое создание, бюджет точной дедупликации и сохранение первых выборов. В PostgreSQL/Kafka реальный интеграционный тест принудительно теряет сессию владения, проверяет остановку допуска, восстановление и точный итог; отдельный тест проверяет незавершённую первоначальную подготовку темы без удаления старых данных.

## Повторение

В каждой ветке:

```sh
make build
make check
```

Полное HTTP-испытание само запускает отдельный процесс, создаёт приватную конфигурацию и останавливает его после проверки:

```sh
# В simple-files, свободный локальный порт:
python3 scripts/check_service.py --mode simple-files --port 8091

# В postgres-kafka; PostgreSQL и три Kafka-брокера должны работать:
TEST_DATABASE_URL='подключение к тестовой БД' \
  python3 scripts/check_service.py --mode postgres-kafka --port 8092
TEST_DATABASE_URL='подключение к тестовой БД' make app-kafka-test
```

Для браузера запустите отдельный тестовый экземпляр через `make dev`, установите зависимости `npm ci`, затем `npx playwright install`, если подходящего браузера ещё нет. Задайте `E2E_BASE_URL` и `ADMIN_PASSWORD` из приватной конфигурации этого экземпляра, выполните `npm run test:e2e`. Сценарий создаёт настоящий опрос с подготовкой 30 секунд и окном 60 секунд. Не запускайте его в каталоге данных рабочего события.

Отчёты хранятся в [measurements/2026-09-10/branches](measurements/2026-09-10/branches). Они содержат агрегаты, без паролей и идентификаторов участников. Приватные конфигурации и полные журналы остаются в игнорируемой `.local`.

## Граница доказательства

Файловая версия зависит от единственного носителя. Kafka-версия имеет одного контроллера приложения и требует отдельных мер для автоматического переключения. Потеря диска, питание и независимые зоны в этой серии не проверялись. Linux-бинарники собираются, но выполнение приложения проверялось на macOS.

Прежний результат более 100 млн записей за минуту относится к пакетному `filebench`. HTTP-сервис использует другое представление записей и дополнительные уровни обработки. Ни одна ветка пока не подтверждена на 1,7 млн HTTP-запросов/с.
