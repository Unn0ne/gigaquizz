# Архитектура simple-files

```text
Браузер → HTTP API → файловый Repository → очередь → WAL + sync → 202 recorded
                 ↘ защищённый кабинет          ↘ пересчёт → result.json
```

Один Go-процесс обслуживает сайт, административную сессию и хранение. Конфигурация и описания опросов загружаются в память. На запрос голосования не требуется обращение к базе данных или сетевому брокеру.

Каждый опрос имеет неизменяемое описание с UUID, вопросом, вариантами и интервалом ровно 60 секунд. Создание пересекающихся интервалов запрещено. Создание сначала готовит служебный каталог, затем атомарно публикует его под ID опроса; незавершённая подготовка не ломает ранее сохранённые опросы. Владелец всего каталога удерживает блокировку ОС, а журнал дополнительно защищён от второго writer.

`POST /api/polls/{id}/votes` принимает полный 128-битный случайный ID и выбор. До допуска проверяются формат, варианты, серверный дедлайн и ограничение очереди. `202 recorded` возвращается после полной записи группы и успешной синхронизации. Запись, допущенная до конца окна, может получить ACK позже. `503 unknown` не означает, что запись отсутствует: повтор должен использовать тот же ID и выбор.

Первый выбор определяется порядком WAL. Поэтому подтверждение попытки не является окончательным результатом дедупликации. После закрытия writer дописывает очередь и терминальную запись, затем пересчёт сравнивает полные ID и формирует агрегаты. Для произвольных браузерных ID используется точная таблица ключей; её объём ограничен `MAX_UNIQUE_VOTERS`. Превышение предела или ошибка чтения не публикуют частичный итог как окончательный.

До готовности агрегатов API результатов возвращает `pending: true`. Итоговый JSON публикуется атомарно с синхронизацией файла и каталога. Пользователь видит итог только после успешного завершения этого шага.

После остановки или падения приложение восстанавливает исходные интервалы и журналы. Полный корректный префикс сохраняется. Оборванный последний frame разрешается отдельно от ошибки CRC: повреждение полной записи не замалчивается. Перезапуск не создаёт новую минуту голосования. Закрытый опрос не открывается заново.

На macOS используется F_FULLFSYNC, на Linux — fsync. Полная запись и успешный вызов синхронизации предшествуют ACK. Сохранность зависит от исполнения контракта ОС и устройства; SIGKILL не равен физическому отключению питания. Единственный диск остаётся единственной копией.

Стенд `filebench` передаёт до 4096 логических попыток одним вызовом и ранее сохранил более 100 млн новых ID за минуту. Сайт принимает отдельные HTTP-запросы; затраты HTTP, TLS и представления записей отличаются. Для полного сервиса прежние цифры не являются подтверждением того же RPS.
