# Две версии Gigaquizz

| Ветка | Где описания и итоги | Где попытки голосования | Запуск |
|---|---|---|---|
| `simple-files` | JSON в каталоге данных | Бинарный WAL с синхронизацией диска | Go-процесс, локальный диск |
| `postgres-kafka` | PostgreSQL | Kafka с подтверждёнными транзакциями | Go-процесс, PostgreSQL, Kafka |

Обе версии обслуживают сайт, кабинет, создание опросов, голосование и окончательные результаты. Контракт одинаковый: `202 recorded` подтверждает сохранённую попытку. После закрытия учитывается первый выбор полного браузерного ID. До завершения обработки результаты содержат `pending: true`; кабинет показывает ожидание.

```sh
git switch simple-files
# либо
git switch postgres-kafka
```

`make dev` и `make run` выбирают отдельную конфигурацию: `.env.simple-files` (порт 8091) или `.env.postgres-kafka` (порт 8092). Обычный `.env` не изменяется. Свой файл можно выбрать через `GIGAQUIZZ_ENV_FILE`; для прямого запуска бинарника укажите `-env /path/to/private.env`.

Для одновременного запуска используйте отдельные каталоги checkout/worktree, разные HTTP-порты и отдельные настройки. Файловый каталог и PostgreSQL/Kafka не являются взаимозаменяемыми форматами: переключение ветки не переносит опросы между хранилищами. Сохранённые данные остаются доступны своей версии.

`simple-files` проще в эксплуатации, но имеет одну локальную копию и одного владельца. Репликация Kafka в `postgres-kafka` защищает в рамках настроенного кластера; единственный контроллер приложения не обеспечивает автоматическое переключение сервиса на другой хост. Ни одна ветка не объявляется готовой к 1,7 млн HTTP-запросов/с без отдельного сетевого испытания.

[Проверенные сценарии и команды](branch-verification.md). Документы о прежних архитектурных экспериментах сохранены для истории; актуальные инструкции находятся в README соответствующей ветки.
