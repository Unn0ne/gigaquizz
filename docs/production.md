# Размещение simple-files

Минимальная рабочая топология этой ветки — один Go-процесс и локальный диск, с HTTPS-прокси для внешнего доступа. PostgreSQL, Kafka и парк из 39 машин не являются её зависимостями. [Другая ветка](branches.md) сохраняет вариант с PostgreSQL/Kafka.

Количество серверов для **100 млн реальных HTTP-голосований за минуту** ещё не подтверждено испытанием полного сервиса. Пакетное файловое ядро уже проходило 1,7 млн логических попыток/с, но это другой уровень измерения. [Результаты ядра](file-results.md), [проверки полного сервиса](branch-verification.md).

Для первого серверного испытания разумно выделить отдельный узел с 32 GiB RAM, современным многоядерным CPU и локальным NVMe, а генераторы разместить отдельно. Это конфигурация испытания, не обещание достаточной мощности production. Точную память пересчёта и устойчивый HTTP RPS измеряйте на целевой ОС; macOS-результат не переносится автоматически на Linux.

Файловый HTTP Repository сейчас записывает отдельный frame на запрос: 40 B заголовка и 28 B полей — около 6,8 GB на 100 млн попыток, около 113,3 MB/s логических данных. Sync объединяет несколько frames. С повторами объём растёт пропорционально. Это отличается от filebench, где до 4096 попыток упакованы в один frame и размер около 2,8 GB. Не планируйте HTTP-хранилище по меньшей цифре стенда.

Таблица полных ID при окончательном пересчёте требует дополнительной памяти, зависящей от числа уникальных ключей. `MAX_UNIQUE_VOTERS` ограничивает этот этап; `MAX_INFLIGHT`, размер очереди и группы sync ограничивают приём. Значения по умолчанию подходят для запуска и испытаний, а их повышение требует повторного измерения задержки и ресурсов.

Если запрос занимает условный 1 KiB на входе, 1,7 млн запросов/с дают около 13,9 Gbit/s до дополнительного overhead. Ответы, TLS, соединения и страница добавляют расходы. Один локальный файл не устраняет сетевые ограничения.

Этот вариант переживает проверенные перезапуски процесса при сохранном носителе. Потерю хоста или диска одна копия не покрывает. Если это обязательное требование события, требуется репликация и переключение владельца; число независимых узлов определяется этой моделью отказов и измеренной производительностью.
