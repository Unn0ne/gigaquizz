Общий API веток `simple-files` и `postgres-kafka`. Все тела — JSON; идентификаторы голосующих не передаются в URL. Ответы API имеют `Cache-Control: no-store`; CDN-кеширование публичного описания опроса будет отдельным изменением протокола времени. Статика кешируется отдельно.

| Метод и путь | Доступ | Результат |
|---|---|---|
| `GET /healthz` | Без авторизации | Жив ли HTTP-процесс |
| `GET /readyz` | Без авторизации | Последняя фоновая проверка хранилища, 200/503 |
| `POST /api/admin/login` | Пароль в JSON | Сессионная HttpOnly cookie, 200/401/429 |
| `POST /api/admin/logout` | Cookie | Отзыв текущей сессии, 204 |
| `GET /api/admin/session` | Cookie | 200/401 |
| `GET /api/admin/polls` | Cookie | До 100 опросов и серверное время |
| `POST /api/admin/polls` | Cookie | Создание, 201; пересечение окон, 409 |
| `GET /api/admin/polls/{id}/results` | Cookie | Число голосов и счётчики вариантов |
| `GET /api/admin/metrics` | Cookie | Счётчики процесса без полей участников |
| `GET /api/polls/{id}` | Без авторизации | Описание, расписание, состояние, серверное время |
| `POST /api/polls/{id}/votes` | Без авторизации | Сохранение попытки голосования |

Создание:

```json
{"question":"Когда встречаемся?","type":"single","options":["Утром","Вечером"],"starts_at":"2026-09-12T12:00:00Z"}
```

`starts_at` можно опустить/null: файловая версия начинает после создания, Kafka-версия предусматривает время подготовки до старта. Точное окно всегда возвращается в ответе; клиент ориентируется на него. Длительность всегда 60 секунд. Поля ответа: `id`, `question`, `type`, `options:[{id,label}]`, `starts_at`, `ends_at`, `created_at`, необязательный `finalized_at`, `state`, `server_time`. Типы: `ab`, `single`, `multiple`. Выборы нумеруются от 1, после создания не редактируются.

Голос:

```json
{"token":"000102030405060708090a0b0c0d0e0f","choices":[1]}
```

Пример токена выше предназначен только для описания; клиент создаёт 16 случайных байт и передаёт 32 строчных hex-символа. Порядок `choices` нормализуется, дубли внутри массива запрещены. Разрешённый размер тела голосования — 4096 байт, административного создания — 16384 байта. Неизвестные поля отклоняются; IP/fingerprint не входят в контракт.

| HTTP | `status` / `outcome` | Смысл и действие клиента |
|---|---|---|
| 202 | `recorded` | Попытка надёжно сохранена; `choices` относится к этой попытке, `accepted_at` — время её допуска. Окончательный первый выбор определяется при пересчёте |
| 410 | `closed` | Эта попытка не допущена после закрытия; это не отменяет сохранённую ранее попытку |
| 425 | `not_open` | Голосование ещё не началось |
| 422 | `invalid` или `error` | Неверные варианты/токен/размер набора |
| 404 | `not_found` или `error` | Опрос не найден |
| 503 | `outcome: unknown` | Запись могла состояться; сохранить тот же ключ и выбор, повторить проверку |
| 503 | `outcome: not_admitted` | Этот HTTP-запрос отклонён до допуска из-за лимита; более ранняя попытка всё ещё могла состояться |

Тайм-аут соединения не доказывает отказ. Клиент никогда не заменяет ключ при повторе. Ошибки сервера не содержат SQL, пароль подключения или содержимое голоса. Для других ошибок используется `{ "error": "описание" }`.

Автоматических повторных POST в браузере нет. После неопределённого исхода ручная кнопка получает случайную задержку 1–2, 2–4, затем 4–8 секунд; Retry-After в секундах задаёт нижнюю границу. Таймер только разблокирует кнопку, сохраняются прежние ID/выбор. После перезагрузки задержка сбрасывается. Серверное время в публичном описании используется для интерфейса; окончательное решение о допуске принимает владелец журнала.

После дедлайна новые POST, включая повтор прежнего ID, не добавляют записи. Повтор до закрытия может сохранить дополнительную попытку; пересчёт учитывает один первый выбор ID. Ранее полученная квитанция сохраняется браузером, но отдельного серверного поиска квитанции по ID в этих ветках нет.

Состояния опроса: `scheduled` → `open` → `processing` → `final`. `processing` означает, что новые голоса закрыты, а ранее допущенные операции и/или финальный подсчёт ещё завершаются. Серверный `accepted_at` относится к моменту допуска после проверки вариантов и ожидания блокировки; подтверждение приходит после сохранения записи. Первое чтение байтов HTTP не является допуском.

Результаты:

```json
{"poll_id":"…","state":"final","total_votes":2,"options":[{"id":1,"label":"Утром","votes":1},{"id":2,"label":"Вечером","votes":1}],"calculated_at":"2026-09-12T12:01:01Z"}
```

`total_votes` считает принятые уникальные браузерные ключи, не доказанное число людей. Для multiple choice сумма вариантов может превышать `total_votes`. До окончания пересчёта ответ имеет `pending: true`: числовые поля ещё не являются итогом и кабинет показывает ожидание. Окончательный ответ имеет `state: final` без `pending: true`; агрегаты публикуются после барьера завершения записи и сохранения результата.

Административная cookie действует до 8 часов, хранится HttpOnly, SameSite=Strict, Secure при HTTPS. Сервер хранит хеш сессионного токена и время истечения в ограниченной памяти, отзыв действует сразу. Перезапуск требует повторного входа. Поддержка нескольких независимых административных процессов с общими сессиями/OIDC ещё не реализована. Для браузерных изменений проверяются Origin/Referer и Sec-Fetch-Site; CORS не включён. Внешнее размещение требует HTTPS, соответствующего `PUBLIC_URL` и закрытого доступа к хранилищу.
