Интеграционные сценарии PostgreSQL проверяют конкурентные одинаковые и разные ответы с одним ID, fresh snapshot после ожидания победившего INSERT, запрет пересекающихся расписаний, commit после закрытия для ранее допущенного голоса, ожидание старого commit/rollback при позднем повторе, `unknown` при пересечении дедлайна, отмену запроса, прекращение backend с незакоммиченной транзакцией и восстановление квитанции после переподключения. Каждый тест использует отдельную случайную схему. Это не испытание потери зоны, региона или диска.

Браузерный сценарий проверяет две вкладки одного контекста с конкурентными отправками: один ID и один исходный выбор, один учтённый голос. В другом браузерном контексте первый реальный запрос сохраняется сервером, а подтверждение намеренно обрывается тестом; после перезагрузки повтор восстанавливает квитанцию без второго голоса. После реальной минуты новые ключи отклоняются, прежняя квитанция читается, окончательное число равно двум. Административный доступ и отзыв сессии проверены через UI/API.
