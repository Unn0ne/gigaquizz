# Повторная проверка двух веток

13 сентября 2026. [Выводы и исправления](../../../recheck.md).

В каталоге сохранены агрегаты четырёх последовательных минутных HTTP-профилей, полного браузерного набора до/после, Go/Python проверок и контрольные суммы исходников/бинарников. `summary.json` отдельно показывает сверку журнала и полноту приёма всего плана. Сохранённые ACK совпали с журналами; поздние отказы не скрыты.

Приватные планы, seed, идентификаторы, эталоны попыток, конфигурации и пароли остаются в `.local`. Сырые логи процессов и их PID не публикуются. Наблюдения CPU/RSS получены из выборок, не являются точным максимумом и относятся к общей машине.

Для повторения нужны собранные `bin/gigaquizz`, `bin/httpbench`, свободный локальный порт и запас диска. Kafka должна быть подготовлена, `TEST_DATABASE_URL` — задан в частном окружении. Используйте новый label; старые каталоги не перезаписываются. В своей ветке:

```sh
make build
# simple-files: POST 50k/s, два генератора, одна партиция
python3 scripts/profile_full_http.py --mode simple-files --label repeat_files_50k --rate 50000 --workers 1024 --generators 2
# postgres-kafka: POST 20k/s, 16 партиций
python3 scripts/profile_full_http.py --mode postgres-kafka --label repeat_kafka_20k --rate 20000 --workers 4096 --partitions 16 --batch-votes 1024
```

Для сценария открытия страницы: `--rate 1000 --workers 256 --generators 2 --repeat-every 7 --journey --definition --max-lag-ms 1000`; дополнительно files `--file-partitions 8`, Kafka `--partitions 8 --batch-votes 1024`. Нагрузка только локальная; эти результаты не подтверждают 100 млн пользователей за минуту.
