Агрегатные артефакты CPU-only серии — 10.09.2026

[Основной отчёт](../../../core-results.md), [методика и команды](../../../core-benchmark.md), [сводные значения](summary.json).

| Префикс файла | Сценарий |
|---|---|
| `smoke_1000_repeat5` | Первый контроль, 1000 новых ID/с + 20% повторов; нагрузка закончилась, Seal вызван слишком рано, полной сверки нет |
| `smoke_1000_repeat5_wallfix` | Контроль после исправления ожидания серверного дедлайна; 74 пропущенные попытки, полная сверка успешна |
| `target_1700k_w8` | 102 млн запланированных новых ID; max-lag 20ms, фактически 101 448 420 принятых |
| `headroom_1800k_w8_lag100` | Все 108 млн новых ID приняты за минуту, max-lag 100ms |
| `headroom_1800k_w8_repeat20_lag100` | Все 108 млн новых ID и 5,4 млн конфликтующих повторов обработаны за минуту |

Для каждого профиля `.json` содержит счётчики попыток, серверные границы, выборочные latency-гистограммы, секундные корзины, диагностику памяти и полную сверку принятых ключей. `_telemetry.json` содержит команду, SHA-256 бинарника, среду и секундные отсчёты CPU time/RSS. `.stderr` содержит краткие сообщения о фазах, без ключей участников. `summary.json` сводит числа и отдельно подтверждает проверку равенства плановых попыток сумме отправленных и пропущенных, а отправленных — сумме всех исходов. CPU в сводке вычислен по приросту CPU time между первым и последним секундным отсчётом внутри окна; это среднее за указанный интервал, не пик.

Из публичных копий удалён путь `private_replay_manifest`. AES-ключи, ID опросов и bitmap синтетических выборов находятся только в `.local/corebench` с правами 0600. Опубликованные файлы не позволяют повторно проверить исчезнувшее RAM-состояние после завершения процесса. Полная сверка выполнялась при жизни каждого процесса и не доказывает долговечность данных.

`final-tests.log` — проверки всех пакетов с race detector, реальными PostgreSQL/Kafka, vet и сборка пяти бинарников. `verification.json` — команды и контрольные суммы нового кода. `final-kafka-status.json` — восстановленная готовность трёх локальных брокеров после CPU-эксперимента. Эти проверки не являются испытанием отказа во время новых RAM-нагрузок.
