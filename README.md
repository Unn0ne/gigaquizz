# Gigaquizz

Опросы на одну минуту: создайте вопрос, поделитесь ссылкой или QR-кодом и посмотрите результаты в кабинете. Участникам не нужна регистрация, кабинет организатора защищён паролем.

Можно выбрать один или несколько вариантов ответа. Через 60 секунд голосование закрывается. При повторном заходе из того же браузера учитывается первый сохранённый ответ. Это базовая защита от повторов, а не проверка личности.

Это ветка **simple-files**: одно Go-приложение, данные в файлах, без базы данных и брокера сообщений. Версия с PostgreSQL и Kafka — в [отдельной ветке](https://github.com/Unn0ne/gigaquizz/tree/postgres-kafka).

## Запустить у себя

Для запуска на macOS или Linux нужны **Go 1.26.1+, Python 3 и make**:

```sh
git clone --branch simple-files https://github.com/Unn0ne/gigaquizz.git
cd gigaquizz
make dev
```

Откройте **http://127.0.0.1:8091/admin**. Пароль находится в `ADMIN_PASSWORD` в созданном файле `.env.simple-files`. Создайте опрос — в кабинете появятся ссылка и [QR-код](docs/qr.md), который можно скачать в PNG.

Данные сохраняются в `.local/files`. Для резервной копии нужен весь каталог после остановки приложения. Потеря единственного диска означает потерю данных. Чтобы участники открывали опрос с других устройств, настройте доступный им адрес `PUBLIC_URL` — [инструкция](docs/launch.md).

`make check` запускает проверки, `make build` собирает приложение. Готовому бинарнику на сервере Go и Python не нужны: Python используется в скриптах запуска, сборки и тестирования.

## Какое железо нужно для 100 млн участников

100 млн голосов за минуту — **1,67 млн голосов/с**. Для планирования считаем 20% повторных попыток: **2 млн попыток голосования/с**, с загрузкой CPU и сети до 70%.

**Это расчётный ориентир, не подтверждённые минимальные требования.** CPU оценён по замерам на ноутбуке: перенос этой мощности на сервер и масштабирование одного процесса ещё нужно проверить.

| Компонент | Количество | CPU, условных ядер | RAM | Свободное место под данные | Сеть |
|---|---:|---:|---:|---|---|
| Приложение и файловый журнал | 1 сервер | ≈128 | 32 GiB | 100 GB на локальном NVMe | 25GbE |

«Условные ядра» обозначают мощность по исходным замерам, а не столько же vCPU любого облака. Если уменьшить CPU-затраты на запрос примерно вдвое, ориентир снизится до 64 ядер; такой результат ещё не получен.

Один опрос с повторами занимает около **3,4 GB** журнала. 100 GB — запас под несколько опросов и копии, без системного раздела. История сама не удаляется. Для диска важны быстрый `fsync` и защита от потери питания.

**CDN/прокси считаются отдельно:** они должны кэшировать страницу и статику, принимать HTTPS и переиспользовать ограниченный пул соединений к приложению. Сеть 25GbE рассчитана на голосование при примерно 1 KiB в каждом направлении на попытку; весь сайт без кэша в этот бюджет не входит.

Для переноса используйте [серверную инструкцию](docs/server-deployment.md), а не настройки `make dev`. В серверном шаблоне пока стоит `GOMEMLIMIT=96GiB`: для машины с 32 GiB начните с `20GiB` и уточните по замерам. Автоматического переключения на запасной сервер нет.

Все формулы, допущения и ограничения — в [расчёте железа](docs/hardware-sizing.md).
