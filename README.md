# Gigaquizz — PostgreSQL + Kafka

Ветка `postgres-kafka`: работающий сайт опросов, кабинет администратора и Go-сервис. PostgreSQL хранит вопросы, расписание и окончательные результаты. Попытки голосования записываются в Kafka; SQL в пути отправки голоса отсутствует.

- Один опрос длится ровно 60 секунд. Варианты: A/B, один или несколько ответов.
- `202 recorded` подтверждает сохранённую транзакцией Kafka попытку. После закрытия учитывается первый записанный выбор полного случайного ID браузера.
- До полного пересчёта кабинет показывает ожидание. Итог и `FinalizedAt` сохраняются в PostgreSQL и доступны после перезапуска.
- Один контроллер приложения владеет схемой и писателями Kafka. Параллельный запуск с той же схемой запрещён.

Нужны **Go 1.26.1+, PostgreSQL 16+ и Kafka с тремя брокерами**. Для native Kafka-стенда дополнительно нужны Python 3.11.4+ и Java 21; [скрипт стенда](docs/kafka-lab.md) использует локальные каталоги проекта.

```sh
git switch postgres-kafka
make kafka-up
make dev
```

`make dev` готовит локальный PostgreSQL и создаёт `.env.postgres-kafka` со случайным паролем администратора. По умолчанию кабинет доступен на **http://127.0.0.1:8092/admin**; пароль указан в `ADMIN_PASSWORD`. Для существующих PostgreSQL/Kafka скопируйте `.env.example` в `.env.postgres-kafka`, настройте подключения и выполните `make run`.

Обе команды используют `.env.postgres-kafka`; `GIGAQUIZZ_ENV_FILE` задаёт другой файл, например `GIGAQUIZZ_ENV_FILE=.env.kafka-test make run`. Существующие `.env` и `.env.simple-files` не изменяются и автоматически не читаются этими командами.

В worktree с уже запущенной инфраструктурой используйте отдельные порт и схему: `HTTP_ADDR=127.0.0.1:8092`, `PUBLIC_URL=http://127.0.0.1:8092`, `GIGAQUIZZ_SCHEMA=gigaquizz_kafka_site`. Второй Kafka-стенд на занятых портах запускать не нужно. [Настройка и восстановление](docs/postgres-kafka.md).

При выборе «сейчас» сервис выделяет 20 секунд на подготовку Kafka перед началом минутного опроса. Будущий старт должен учитывать этот запас. Если создание не подтвердилось, сначала проверьте список: описание могло уже сохраниться, а подготовка продолжится контроллером.

```sh
make build
make check
TEST_DATABASE_URL='ваше подключение' make app-kafka-test
```

Интеграционный тест использует собственные схему, темы и HTTP-порт. Он проверяет повторные попытки, потерю сессии владения, восстановление внутри и после минуты, точный итог и его чтение после перезапуска.

Это функциональная ветка с единственным контроллером приложения. Она не обеспечивает автоматическое переключение Go-процесса и не доказывает 1,7 млн HTTP-запросов/с. Kafka ACK не означает отдельный `fsync` каждой копии.
