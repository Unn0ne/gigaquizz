# Gigaquizz

Опросы на одну минуту: создайте вопрос, поделитесь ссылкой или QR-кодом и посмотрите результаты в кабинете. Участникам не нужна регистрация, кабинет организатора защищён паролем.

Можно выбрать один или несколько вариантов ответа. Через 60 секунд голосование закрывается. При повторном заходе из того же браузера учитывается первый сохранённый ответ. Это базовая защита от повторов, а не проверка личности.

Это ветка **postgres-kafka**: Go-приложение принимает голоса, Kafka сохраняет их в трёх копиях, PostgreSQL хранит вопросы и итоги. Каждый голос в PostgreSQL не записывается. Более простая версия без этих служб — [simple-files](https://github.com/Unn0ne/gigaquizz/tree/simple-files).

## Запустить у себя

На macOS или Linux нужны **Go 1.26.1+, Python 3.11.4+, make, Java 21+**, а также **PostgreSQL 16+ или Docker Compose**:

```sh
git clone --branch postgres-kafka https://github.com/Unn0ne/gigaquizz.git
cd gigaquizz
make kafka-up
make dev
```

`make kafka-up` подготовит три локальных брокера Kafka. `make dev` подготовит PostgreSQL и запустит приложение.

Откройте **http://127.0.0.1:8092/admin**. Пароль находится в `ADMIN_PASSWORD` в созданном файле `.env.postgres-kafka`. Создайте опрос — в кабинете появятся ссылка и [QR-код](docs/qr.md), который можно скачать в PNG. В локальных настройках старт «сейчас» даёт 20 секунд на подготовку, затем начинается минута голосования.

Если PostgreSQL и Kafka уже работают, заполните `.env.postgres-kafka` по примеру `.env.example` и выполните `make run`. Для доступа с других устройств задайте доступный участникам `PUBLIC_URL`. [Подключение служб и восстановление](docs/postgres-kafka.md), [локальная Kafka](docs/kafka-lab.md).

`make check` запускает проверки, `make build` собирает приложение. Готовому бинарнику Go и Python не нужны; Java нужна брокерам Kafka. Python используется в скриптах запуска, сборки и тестирования.

## Какое железо нужно для 100 млн участников

100 млн голосов за минуту — **1,67 млн голосов/с**. Для планирования считаем 20% повторных попыток: **2 млн попыток голосования/с**, с загрузкой CPU и сети до 70%.

**Это расчётный ориентир, не подтверждённые минимальные требования.** CPU приложения оценён по замерам на ноутбуке: перенос этой мощности на сервер и масштабирование одного процесса ещё нужно проверить. Значения ниже указаны **на один экземпляр**.

| Компонент | Количество | CPU, условных ядер | RAM | Свободное место под данные | Сеть |
|---|---:|---:|---:|---|---|
| Go-приложение | 1 | ≈128–192 | 32 GiB | ОС и служебные файлы; голоса в Kafka | 25GbE |
| Брокер Kafka | 3 | 16–48 | 16 GiB | 100–200 GB NVMe | 10GbE |
| PostgreSQL | 1 | 2–4 | 4–8 GiB | 20–40 GB SSD, история и WAL отдельно | Внутренняя сеть |
| Контроллер Kafka, если вынесен отдельно | 3 | 2 | 8 GiB | 20 GB SSD | Внутренняя сеть |

«Условные ядра» обозначают мощность по исходным замерам, а не столько же vCPU любого облака. Для Kafka важны размер пачек голосов и скорость подтверждения транзакций: увеличение CPU само по себе не гарантирует нужную пропускную способность.

Компактный стенд — **4 сервера**: приложение вместе с PostgreSQL и три брокера вместе с контроллерами. При совмещении CPU и RAM складываются. При полном разделении ролей получается **8 серверов**, из них только один — сервер приложения. Для критичного запуска контроллеры лучше отделить от брокеров. Автоматического переключения приложения и PostgreSQL на запасной узел сейчас нет.

Один опрос с повторами — около **10,3 GB** полезных данных с учётом трёх копий. Планируйте 15–25 GB на кластер с накладными расходами, отдельно место под историю и служебные данные. История сама не удаляется.

**CDN/прокси считаются отдельно:** они должны кэшировать страницу и статику, принимать HTTPS и переиспользовать ограниченный пул соединений к приложению. Сеть 25GbE рассчитана на голосование при примерно 1 KiB в каждом направлении на попытку; весь сайт без кэша в этот бюджет не входит.

Для переноса используйте [серверную инструкцию](docs/server-deployment.md), а не настройки `make dev`. В серверном шаблоне пока стоит `GOMEMLIMIT=96GiB`: для приложения на машине с 32 GiB начните с `20GiB` и уточните по замерам. Все формулы и допущения — в [расчёте железа](docs/hardware-sizing.md).
