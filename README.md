# Gigaquizz

Опросы на одну минуту: создайте вопрос, поделитесь ссылкой или QR-кодом и посмотрите результаты в кабинете. Участникам не нужна регистрация, кабинет организатора защищён паролем.

Можно выбрать один или несколько вариантов ответа. Через 60 секунд голосование закрывается. При повторном заходе из того же браузера учитывается первый сохранённый ответ. Это базовая защита от повторов, а не проверка личности.

## Какую ветку выбрать

`main` — общая страница проекта. Для запуска выберите одну из двух рабочих веток:

| Ветка | Как устроена | Когда выбрать |
|---|---|---|
| [simple-files](https://github.com/Unn0ne/gigaquizz/tree/simple-files) | Одно Go-приложение, данные в файлах | Проще запустить и обслуживать; единственный диск нужно беречь и копировать |
| [postgres-kafka](https://github.com/Unn0ne/gigaquizz/tree/postgres-kafka) | Голоса в Kafka с тремя копиями, вопросы и итоги в PostgreSQL | Нужны реплики журнала и есть возможность обслуживать эти службы |

## Попробовать локально

Начать проще с **simple-files**. На macOS или Linux понадобятся **Go 1.26.1+, Python 3 и make**:

```sh
git clone --branch simple-files https://github.com/Unn0ne/gigaquizz.git
cd gigaquizz
make dev
```

Откройте **http://127.0.0.1:8091/admin**. Пароль находится в `ADMIN_PASSWORD` в созданном файле `.env.simple-files`. Создайте опрос — в кабинете появятся ссылка и [QR-код](https://github.com/Unn0ne/gigaquizz/blob/simple-files/docs/qr.md), который можно скачать в PNG.

Для доступа с других устройств настройте `PUBLIC_URL` — [инструкция](https://github.com/Unn0ne/gigaquizz/blob/simple-files/docs/launch.md). Запуск PostgreSQL/Kafka описан в [README этой ветки](https://github.com/Unn0ne/gigaquizz/blob/postgres-kafka/README.md). Готовому бинарнику приложения на сервере Go и Python не нужны.

## Какое железо нужно для 100 млн участников

100 млн голосов за минуту — **1,67 млн голосов/с**. Для планирования считаем 20% повторных попыток: **2 млн попыток голосования/с**, с загрузкой CPU и сети до 70%.

**Это расчётный ориентир, не подтверждённые минимальные требования.** CPU приложения оценён по замерам на ноутбуке: перенос этой мощности на сервер и масштабирование одного процесса ещё нужно проверить. Значения ниже указаны **на один экземпляр**.

| Ветка / компонент | Количество | CPU, условных ядер | RAM | Свободное место под данные | Сеть |
|---|---:|---:|---:|---|---|
| simple-files: приложение и журнал | 1 | ≈128 | 32 GiB | 100 GB локального NVMe | 25GbE |
| postgres-kafka: приложение | 1 | ≈128–192 | 32 GiB | ОС и служебные файлы; голоса в Kafka | 25GbE |
| postgres-kafka: брокер Kafka | 3 | 16–48 | 16 GiB | 100–200 GB NVMe | 10GbE |
| postgres-kafka: PostgreSQL | 1 | 2–4 | 4–8 GiB | 20–40 GB SSD, история и WAL отдельно | Внутренняя сеть |
| postgres-kafka: отдельный контроллер Kafka | 3 | 2 | 8 GiB | 20 GB SSD | Внутренняя сеть |

«Условные ядра» — оценка мощности по исходным замерам, а не столько же vCPU любого облака. Для Kafka результат также зависит от размера пачек голосов и задержки транзакций. Формулы и ограничения — в [полном расчёте](https://github.com/Unn0ne/gigaquizz/blob/simple-files/docs/hardware-sizing.md).

Файловой версии нужен **один сервер**. Для PostgreSQL/Kafka компактный стенд — **четыре** при совмещении приложения с PostgreSQL и брокеров с контроллерами; при полном разделении ролей — **восемь**. При совмещении бюджеты CPU и RAM складываются. Автоматического переключения приложения на запасной сервер сейчас нет; три копии Kafka этого не заменяют.

Один опрос с повторами занимает около **3,4 GB** файлового журнала или **10,3 GB** полезных данных Kafka с тремя копиями, до её накладных расходов. Терабайт для одного опроса не обязателен, но история сама не удаляется.

**CDN/прокси нужны отдельно:** кэшировать страницу и статику, принимать HTTPS и переиспользовать ограниченный пул соединений к приложению. Сеть 25GbE рассчитана на голосование при примерно 1 KiB в каждом направлении на попытку; весь сайт без кэша в этот бюджет не входит.

Перенос на Linux-сервер: [simple-files](https://github.com/Unn0ne/gigaquizz/blob/simple-files/docs/server-deployment.md) · [postgres-kafka](https://github.com/Unn0ne/gigaquizz/blob/postgres-kafka/docs/server-deployment.md). Серверные шаблоны нужно подстроить под машину: для 32 GiB RAM уменьшить прежний `GOMEMLIMIT=96GiB`, начальный ориентир — `20GiB`.
